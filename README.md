# GameDev PM

**English** · [Türkçe](README.tr.md)

A project management tool for game development teams. It is plain HTML/CSS/JavaScript with no build step, so it runs directly on **GitHub Pages**.

> ### 🤖 Built with Claude
> The code in this repository was generated by **Claude** (Anthropic's AI model, via Claude Code). The team set the requirements, made the design decisions, reviewed the result and tested it. In line with the TÜBİTAK generative AI guideline, this use is also recorded in the app's own **AI use** log.

## Features

| View | What it does |
|---|---|
| **Board** | Trello-style lists and cards. Drag and drop cards and lists (mouse, pen and touch). Cards support a color, colored labels, people, start/due dates, completion, Markdown descriptions, checklists, comments, an activity history, priority, time estimates and dependencies. Bug cards add severity, platforms, build number, steps to reproduce and expected/actual behavior. |
| **Gantt** | Built automatically from cards. Day/week/month zoom; group by list, person or label; collapsible summary bars with progress fill. Milestones, dependency arrows (broken ones in red), critical path and a today line. Drag a bar to move its dates, drag an edge to change its length, drag from the dot on its right onto another bar to add a dependency. Exports to **SVG/PNG**. |
| **Calendar** | Month view with multi-day bars. Drag to reschedule; click a day to add a card. Lists overdue and upcoming work. Exports to Google/Outlook as **.ics**. |
| **Workload** | Person × week (or day) heat map. Estimated hours are spread across workdays; going over capacity shows in red. Exports to SVG/PNG. |
| **Stats** | Progress tiles, a burndown chart, and breakdowns by list, person, label, priority and type. Every chart exports to SVG/PNG. |
| **GDD / Wiki** | Markdown pages with live preview, plus templates for a GDD, character sheets, level design and meeting notes. |
| **AI use** | A generative AI usage log that follows TÜBİTAK's guideline. Details below. |

Also:
- **Search and filter:** type `#label`, `@person` or free text in the search box. The filter panel narrows by status, label, person, priority and type. The filter applies to the board, Gantt, calendar, workload and stats at once.
- **Backgrounds:** 12 presets, a solid color, an image link or an uploaded image.
- **Theme and language:** light/dark theme and Turkish/English follow the system setting by default. Change them from the top bar or Settings.
- **Multiple boards**, Trello JSON import, and full JSON backup and restore.
- **Shortcuts:** `/` focuses search, `1`–`7` switch views, `Esc` closes a dialog.

## AI use section (TÜBİTAK guideline)

Based on the applicants' section of TÜBİTAK's *Guideline on the Responsible and Reliable Use of Generative AI in Research Funding Processes* (v04, January 2026):
- **Areas of use:** *supportive* uses from section 1.1.1 (research, language/translation, coding, ideation, visualization suggestions) and uses *requiring close attention* from 1.1.2 (drafting, data analysis, image generation) are grouped separately. For game projects, audio/music generation and game content (dialogue, story, levels) were added to the *requiring close attention* group.
- **Declaration fields (1.2):** tool name and version, the stage or section where it was used, and the nature and scope of the use. Each entry also records the purpose, the team's contribution, related cards and a "significant use" flag.
- **Verification list (1.3–1.5):** output verified, no confidential or personal data entered, license/IP checked, originality/plagiarism checked, reviewed for bias. Some items are required depending on the area of use; open items show as warnings.
- **Declaration report:** builds a summary table, details per tool and a statement from the log. Copy it, download it as `.md`, or print it to PDF. Entries also export to CSV.

## Publishing on GitHub Pages

1. Push this folder to a GitHub repository (`index.html` must be at the root).
2. Go to **Settings → Pages → Build and deployment**, choose *Deploy from a branch*, then `main` and `/ (root)`.
3. After a minute or two, the site is live at `https://USERNAME.github.io/REPO/`.

To try it locally, any static server works:

```bash
python -m http.server 5173
```

Then open `http://localhost:5173`. Opening `index.html` by double-clicking also works, but Drive sync needs an `http(s)` address.

## Sync with Google Drive

Data is always saved in the browser first (localStorage), so the app works offline. To share it with your team, it syncs through a single JSON file in Google Drive.

### Who sees what?

- The project lives in **one file**. Everyone the file is shared with sees the same project.
- Another team using the same site creates **its own file** and sees only its own project.
- The app asks only for the `drive.file` permission: it cannot see the rest of anyone's Drive, only files created with the app or picked in it.

### Editing at the same time

Every card, list, comment and so on is a separate record with its own "last changed" timestamp. Changes are merged **record by record**: if Ayşe edits card A while Mehmet edits card B, both changes are kept. Only when two people change **the same card within the same few seconds** does the last save win. Deletions are kept as records too, so a deleted card never comes back from another device.

The file is checked about every 15 seconds. Before uploading, the app downloads the latest file and merges it; if two uploads collide, the next round repairs it.

### Setup (once, by one person, about 15 minutes)

1. Create a project at [console.cloud.google.com](https://console.cloud.google.com).
2. In **APIs & Services → Library**, enable **Google Drive API** and **Google Picker API**.
3. **OAuth consent screen:** choose *External*, enter an app name and add your teammates' Gmail addresses under **Test users**. The app can stay in "Testing" mode (up to 100 test users). To let anyone sign in, publish the app; Google may then ask for details such as a privacy policy and review it.
4. **Credentials → Create credentials → OAuth client ID → Web application.** Under *Authorized JavaScript origins*, add `https://USERNAME.github.io` (and `http://localhost:5173` for local testing).
5. **Credentials → Create credentials → API key.** Restrict it under *Website restrictions* to `USERNAME.github.io/*`.
6. **Project number** (App ID): shown on the *Project info* card on the Cloud Console home page.
7. Put the three values in **`config.js`** and push it to GitHub:

   ```js
   window.GDPM_CONFIG = {
     googleDrive: {
       clientId: '1234567890-abc….apps.googleusercontent.com',
       apiKey: 'AIza…',
       appId: '123456789012',
     },
   };
   ```

   These values are not secrets: every browser can see them anyway. Access is limited by the allowed origins and by Drive sharing. If you leave `config.js` empty, each person can enter the keys in **Settings → Sync** instead.

### For each team member

1. One person clicks **Create a new file in Drive** in **Settings → Sync** and shares the resulting `gamedev-pm-data.json` in Drive with the team as **Editor**.
2. Everyone else opens the site, clicks **Connect** in the top bar, and opens the shared file once with **Pick from Drive**.
3. In **Settings → General → Who am I?**, each person picks their own name so comments and logs show it.

The sign-in token lasts about an hour; when it expires, one click on **Connect** in the top bar is enough.

## Backups

**Settings → Data → Export everything** writes everything to one JSON file. Make a backup now and then, even with sync on.
